# Ocarina of Time (2026) data pack

The OoT remake map is a **read-only data pack**, not rows in the database:
JSON in `data/OoT/` and map tiles in `tiles/oot/`, generated by the scripts
in `dev/assets/oot/`. It's a stand-in until full game data is available and
OoT can be imported into the site like the other games.

- **Game id** 64; maps 64xxx (Hyrule is 65000); submaps 64xxxx (Hyrule
  Child 650000, Adult 650001); markers 641xxxxx Heart Pieces, 642xxxxx Gold
  Skulltulas, 643xxxxx Big Poes. **These IDs never change:** completions,
  bookmarks and shared links use them.
- `lib/common/oot_pack.php` reads the pack. The public data endpoints
  (`get_games`, `get_container`, `get_map`, `get_categories`, `get_markers`)
  answer from it for `OoT`, `OoTR` or `64`.
- Anything that finds markers or categories through the database needs its
  own OoT branch (`ootPackIsGame()`). Completions, offline maps, admin stats,
  link previews, category pages and the sitemap already have one.

## Moving or rewording markers

Needs only Node.

1. Edit `dev/assets/oot/pois.json`, one entry per collectible:
   - `age` is `child`, `adult` or `both`.
   - On Hyrule, a position is `region` plus `u`, `v`: a spot inside that
     area's artwork, 0–1 across and 0–1 down. Markers therefore move with
     their area when the layout changes.
   - In dungeons, give `submap`, `x` and `y` instead.
   - `how` (and an optional `needs`) is the marker's text.
2. Regenerate the markers:

   ```sh
   node dev/assets/oot/pois-to-markers.cjs --write
   ```

3. Run the tests (`npm test`), then commit both `pois.json` and
   `data/OoT/markers.json`.

To find `u`, `v`: each area's box on the Hyrule canvas is in
`dev/assets/oot/world-boxes.json` as `[left, top, width, height]` in
pixels. The zoom-5 tiles (`tiles/oot/hyrule-child/5_x_y.webp`, 32 × 32
tiles of 256 px) are that canvas. Then `u = (pixelX − left) / width` and
`v = (pixelY − top) / height`.

## Moving Hyrule's regions

The Hyrule map is composed from each region's artwork, placed by
**`dev/assets/oot/world-layout.json`**:
- `regions`: `[area, centreX, centreY, width]` on an 8,192 px canvas. Width
  is for the Child artwork; Adult artwork is drawn at the same scale.
- `adultShift`: nudges one area's Adult artwork, `[x, y]` in pixels.
- `margin`: the background's padding around all the areas.

After editing it, rebuild:

```sh
SHARP_MODULE=/path/to/node_modules/sharp node dev/assets/oot/import-assets.cjs /path/to/oot-dump
```

This needs **Sharp** (an image library for Node) and **the original asset
dump**. The dump folders it reads are:
- `OoTR-110-CustomTex-Map-Field`: region artwork, including the `Mini_*`
  images that make up Hyrule;
- `OoTR-110-UI-CustomTex-Map-Dungeon`: dungeon floors;
- `OoTR-110-UI-Icons`: item icons.

**Keep a copy of those three folders somewhere the team can find, and note
the location here.** Without them, Hyrule can't be recomposed.

What the rebuild does:
1. Composes Hyrule from `world-layout.json` and writes each area's box to
   `world-boxes.json`.
2. Re-tiles only the images that changed. Unchanged artwork is skipped by
   its hash.
3. Writes `maps.json` with the place labels and connector lines, and
   `import-report.json` (the tile versions the site uses).
4. **Regenerates `markers.json` from `pois.json`.** Markers follow their
   areas, so nothing in `pois.json` needs changing.

Then run the tests and commit `world-layout.json`, `world-boxes.json`,
`data/OoT/` and the changed `tiles/oot/` folders together.

### Connector lines

The lines between area exits are in `dev/assets/oot/connections.json`:
- each exit is `[area, u, v]` inside an area's artwork, so lines follow
  their areas;
- each link joins two exits, with a route (`d` diagonal first, `h`
  horizontal first, `v` vertical first).

Changing only the lines doesn't need the dump:

```sh
node dev/assets/oot/write-connections.cjs
```
